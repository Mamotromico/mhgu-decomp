# Inventory export (Phase 3 — the ledger seed)

The deterministic Ghidra export that **seeds the committed symbol ledger**. It is a *draft*:
Ghidra never decides identity, boundaries, names, or the progress denominator — it proposes
cut points, and the committed ledger (hand-owned) stays authoritative. See
[`architecture.md`](architecture.md) → *Segmentation seed* and *Ledger & export format*.

Everything this produces is **binary-derived metadata** and lands in the git-ignored
`baserom/work/inventory/` tree. It is **never committed** (see [`AGENTS.md`](../AGENTS.md) →
*Repository hygiene*).

## Running it

```sh
tools/ghidra/inventory.sh              # warm: reuse the cached analysis
tools/ghidra/inventory.sh --reanalyze  # (re)run full auto-analysis first
```

- **Cold** (no cached program): imports `baserom/main.nso` and runs a full auto-analysis. Slow
  (~30 min for the ~14 MB AArch32 image).
- **Warm** (program cached): re-runs only the export script, with the program opened
  **read-only** (the export never mutates it, so no save is attempted). Fast.
- **`--reanalyze`**: re-runs auto-analysis over the cached program. Required **once** if the
  project was previously imported without analysis (e.g. by the PoC's `-noanalysis` import).

A loader-only (`-noanalysis`) import has no functions, so the export is nearly empty — always
analyse before trusting the output.

Overridable via environment: `GHIDRA_HOME` (default `/opt/ghidra`), `INV_WORK` (default
`baserom/work/inventory`), `PROGRAM` (default: the NSO's basename). The driver raises
`GHIDRA_HEADLESS_MAXMEM` to `8G` by default — full analysis overruns Ghidra's 2G default.

## Outputs

All five files are **TSV with a header row**, one record per line, sorted deterministically.
Addresses are 8-digit lowercase hex (image offsets).

### `inventory.tsv` — cut-point candidates → the ledger manifest

| column | meaning |
| --- | --- |
| `addr` | symbol address |
| `kind` | `function` \| `data` |
| `size` | bytes (function body length, or data length) |
| `name` | Ghidra's raw name, **verbatim** (provenance, not identity) |
| `block` | memory block name |
| `class` | `content` \| `metadata` (see *Block classes*) |
| `source` | `Symbol.getSource()` — `DEFAULT` \| `ANALYSIS` \| `IMPORTED` \| `USER_DEFINED` |
| `name_class` | `discovered` \| `generated` (derived) |
| `thunk` `entry` `exported` `noncontig` | `0`/`1` function flags |

### `inventory.nested.tsv` — reference-only symbols → the review table

Never the manifest (a nested entry would re-split a segment; see *Symbol identity &
segmentation*). Columns: `addr`, `kind`, `name`, `block`, `source`, `name_class`, `parent`
(enclosing function entry, or empty).

The loader's `EXTERNAL` stubs and off-image symbols (an address with no containing memory
block) are excluded here as well, so the `EXTERNAL` block is skipped entirely and the
review table holds only real image symbols.

### `inventory.gaps.tsv` — uncovered ranges

Coverage of every **initialized** block claimed by neither a function body nor a defined
`Data` (uninitialized blocks — `bss`, `EXTERNAL` — are skipped). Columns: `block`, `class`,
`addr`, `size`. The ledger generator fills the `content` ranges with address-named `D_<addr>`
blobs so the denominator is complete.

### `inventory.externals.tsv` — imports (`external` kind)

Columns: `name`, `bind`. See *Externals* below.

### `inventory.blocks.tsv` — memory-block extents

Columns: `block`, `class`, `addr`, `size`. Every real block's start and size (both classes
emitted tagged; the synthetic `EXTERNAL` block is skipped, as everywhere). This is the only
record of an *uninitialized* block (`bss` is skipped by the gaps pass) and the only source for
the **last** cut point in a block — the one entry whose extent has no successor to bound it. The
generator uses it to close each block's partition.

## Block classes (`class`)

- **`content`** — the game image: `.text`, `.rodata`, `.rodata.1`, `.data`, `.data.1`, `.bss`.
  The only class that contributes to the ledger's progress denominator.
- **`metadata`** — the ELF dynamic-linking blocks the Switch loader *synthesises*: `.dynstr`,
  `.dynsym`, `.rel.dyn`, `.rel.plt`, `.hash`, `.gnu.hash`, `.dynamic`, `.got`, `.got.plt`,
  `.init_array`. These are regenerated by the link, never reconstructed from source, so the
  generator excludes them. They are still emitted (tagged) so the draft is complete.

The loader's synthetic `EXTERNAL` memory block — where it parks import stubs as placeholder
"functions" — is **skipped entirely**: those symbols are the `.dynsym` imports and are
represented by `inventory.externals.tsv` instead. Counting them as cut-point functions both
double-counted imports and inflated the denominator (755 rows in the first real run).

## Classification rules

- **Functions** (any executable block, except the `EXTERNAL` block) → cut points,
  `kind = function`.
- **Top-level data** in a non-executable block (`.rodata`/`.data`) → cut points,
  `kind = data`. Data living **inside `.text`** (literal pools, jump tables) is reference
  material and lands in the nested file via the symbol pass.
- **Every other program-space symbol** in a real image block that is not the primary symbol
  at a cut-point address — labels inside functions, aliases, params/locals → nested. Symbols in
  the `EXTERNAL` block and off-image symbols (no containing block) are dropped entirely.
- **Imports** → `inventory.externals.tsv` (see below).
- **Gaps** → initialized bytes in neither a function body nor a defined `Data`.
- **One row per symbol; no de-duplication.** Alias resolution is the *ledger generator's* job
  (via the `is_alias` guard), not the export's.

**`name_class`** is `discovered` when the name came from the binary or a human
(`IMPORTED`/`USER_DEFINED`) and `generated` otherwise (`DEFAULT`/`ANALYSIS`). It is derived
from `Symbol.getSource()`, **never** by string-matching the `FUN_`/`DAT_` prefix — the prefix
is Ghidra's *inference* and can shift across analysis runs.

Data is enumerated **where a reference points at it**, so computed-offset blobs can be missed
and boundaries inferred: the export *seeds* the ledger, it does not bound it.

## Externals — parsed from `.dynsym`

Auto-analysis **demangles** external symbols (`_ZN2nn3ldn15MakeIpv4AddressEhhhh` becomes
`MakeIpv4Address`), so the exact Itanium-mangled name — the identity the ledger reproduces,
since the mangling **pins the signature** (parameters + `const`) — no longer exists in the
symbol table. It survives only in the ELF dynamic string table.

So the export parses `.dynsym`/`.dynstr` directly (Elf32_Sym, 16 bytes) and emits every
`SHN_UNDEF` entry as `name` (mangled, verbatim) + `bind` (`LOCAL`/`GLOBAL`/`WEAK`, from
`st_info >> 4`). The mangled name encodes its own namespace, so no separate library column is
needed; the binding is the linker attribute the ledger's relocation check consumes.

Do **not** reconstruct externals from Ghidra's external symbols: those are demangled, and
their ordinals do not map cleanly onto dynsym order (the loader drops a few linker-provided
entries such as `__rela_dyn_start`).

## Known limitations (draft)

- The nested `kind` column is `Symbol.getSymbolType()` and currently collapses to `label` for
  essentially every row — it is not yet discriminating.
- Struct/array *components* are `Data`, not symbols, and are not enumerated (a follow-up).
- `exported` is `Symbol.isGlobal()` — the Ghidra namespace-global test, true for nearly every
  symbol in a stripped image; it carries little signal, and `entry` is the meaningful flag.

## Determinism

The output depends solely on the pinned trio — **Ghidra 12.1.2, the Switch Loader, and the
NSO** — plus sort order. No timestamps, no absolute paths, no machine state. Two runs over the
same inputs are byte-identical.

## Downstream — the committed ledger

`tools/ledger/gen_ledger.py` promotes this draft into the committed ledger
(`config/main/ledger.tsv`, a frozen hand-owned seed; CI is gated by
`tools/ledger/validate.py`) — see
[`architecture.md`](architecture.md) → *Ledger — concrete schema*. It is a near-identity
mapping: content cut points + materialised `content` gaps + externals, with generated names
replaced by `func_<addr>`/`D_<addr>` placeholders.

One transformation is **not** identity: `size`. The export reports a function's **span**
(first…last instruction), which for a non-contiguous body over-covers the next function and
leaves interior bytes untilled, so the ledger re-derives `size` as the distance to the next
cut point in the block (the last entry uses the block end from `inventory.blocks.tsv`) — a
complete, disjoint partition. The export's own `size` is therefore advisory; treat it as a
draft, not a boundary.
